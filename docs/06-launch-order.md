# 06 · 启动顺序和自检

## 顺序别乱

```
1. 打开本地服务端 App，确认界面显示"运行中"
      ↓（可退后台，但不要从最近任务里划掉；它是前台服务）
2. 打开 SFA，启动对应的 profile（状态栏出现 VPN 图标）
      ↓
3. 启动游戏客户端
```

为什么：

服务端得在 VPN 之前就绪。VPN 一起来端口改写马上生效，这时 31000 没人听，头几个 SDK 请求就直接废了。

游戏放最后，是因为客户端只在启动时读一次 SDK 配置、拉一次 serverlist。顺序错了就得重启它。

## 一条命令自检

见 [`scripts/selfcheck.sh`](../scripts/selfcheck.sh)：

```bash
bash scripts/selfcheck.sh
```

依次看：

1. 服务端进程是否存在；
2. `31000` 是否在监听；
3. 是否有 `ESTAB … -> 127.0.0.1:31000`（登录成功后才有）；
4. VPN 是否在运行（`tun` 接口存在）。

## 手动三连

```bash
adb shell pidof com.mikusb.server                 # 服务端进程
adb shell ss -tln | grep 31000                    # 0.0.0.0:31000 LISTEN
adb shell ss -tn  | grep 31000                    # 127.0.0.1:<port> -> 127.0.0.1:31000 ESTAB
```

第三条才是真进去了的判据。只有登录成功、客户端拿到 serverlist 之后，才会建到 31000 的长连接。

## 症状对照

| 症状 | 大概率原因 |
|---|---|
| 初始化报「网络异常」 | 机器上有残留全局 HTTP 代理；或误把 `893` 也做了重定向 |
| 卡「伺服器尚未开放」 | serverlist 规则没命中 → 检查 `sniff` 是否在域名规则之前；或 serverlist 返回格式不对（见下） |
| 点开始游戏毫无反应、服务端收不到 `ReqLogin` | 服务端 serverlist 返回了自定义对象，客户端只认四字段数组 |
| 登录成功但一个文件都不读、退回标题 | 资源清单的 `paks` 是空数组 → 客户端认为资源已齐（见 docs/02） |
| 资源「齐了」还是停在加载画面 | 清单只列了基础 pak，缺 `*_Maps_*`，大厅地图加载不了 |
| 一直提示更新资源 | 本地资源目录版本不匹配（重装/换签名后常见） |
| 进游戏后立刻闪退 | 资源差异下载被触发后主动 `System.exit`，不是崩溃 |
| 重启手机后失效 | 服务端/VPN 都没自启，按上面顺序重来 |

登录后卡住不是回调链断裂，别为此去改 dex。完整的推翻过程在 [02-client-analysis.md](02-client-analysis.md)。
