# 01 · 整体是怎么串起来的

## 组件

| 组件 | 包名 | 职责 | 归属 |
|---|---|---|---|
| 游戏客户端 | `com.seasun.snowbreak.google` | UE4 游戏本体；SDK 登录；资源更新 | 商业闭源，需自备 |
| 本地服务端 | 由上游 MikuSB 提供 | 监听 `0.0.0.0:31000`（游戏协议）；另有本地 TLS 代理端口 | 上游 [MikuSB](https://github.com/MikuLeaks/MikuSB) |
| VPN / 重定向 | `io.nekohasekai.sfa`（sing-box 1.14.x） | tun 截获游戏流量，按端口/域名改写目标地址 | sing-box / SFA |
| serverlist | 服务端附带 | 返回 `[{"platform":"Android_ASTC","version":"…","host":"127.0.0.1","port":31000}]` | 上游 |

服务端和客户端之间其实只约定两件事：一是 `serverlist` 返回的 host/port（决定游戏连哪），二是 31000 上的游戏协议（登录加长连接）。剩下的全是把包送到 `127.0.0.1` 的网络活。

## 启动时序

```
[1] 服务端进程起来
      ├─ 31000  LISTEN 0.0.0.0        （游戏协议）
      └─ 127.0.0.1:13443/18443/21443/31443 （本地 TLS 代理）

[2] VPN 起来（tun 生效，路由表指向 tun）

[3] 游戏启动
      ├─ SDK 初始化     →  https://<sdk>:13443   → 127.0.0.1:13443
      ├─ SDK 探测       →  https://<sdk>:18443   → 127.0.0.1:18443
      ├─ 拉服务器列表   →  https://<domain>:443  → 127.0.0.1:21443  → 得到 127.0.0.1:31000
      ├─ 登录           →  https://<sdk>:31443   → 127.0.0.1:31443
      ├─ 资源更新       →  官方 CDN（直连，不经改写）
      └─ 进游戏         →  TCP <sdk>:5200        → 127.0.0.1:31000
```

## 为什么"资源更新"必须走真实网络

资源（26 GB 级）在官方 CDN 上，本地服务端不给。所以：

- 更新阶段需要正常外网，规则里不改写 CDN 域名；
- 更新完成后进入游戏，流量才全部落在本机。

## 与"PC 方案"的差异

上游 MikuSB 的客户端接入是 Windows 专用的：`Loader` 挂起启动游戏 exe，注入补丁 DLL，由 DLL hook `connect` 把连接改到本机。

安卓上没 root 就没有 `LoadLibrary` 注入，也没有通用的 IAT hook 手段，所以干脆把这一层整个挪到网络层：客户端一个 hook 都不做，由 VpnService 在 IP 层改目标地址。这是跟 PC 方案唯一的结构差别。
